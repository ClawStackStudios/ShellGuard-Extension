# Crypto Law: Key Hierarchy, HKDF-SHA256 & Session Quarantine

Human Sovereign Keys (`hu-`, Base62 $\ge 32$ chars) and Agentic LobsterKeys (`lb-`, Base62 carrying bitwise `canRead`, `canWrite`, `canEdit`, `canDelete` scopes) are never logged, transmitted in plaintext, or written to `chrome.storage.local`. Upon authentication inside the isolated offscreen enclave, the raw secret is imported into WebCrypto (`extractable: false`) to derive a 256-bit Master PRK salted with the account `userUuid`, which then expands 10 independent 256-bit AES-GCM domain keys via $K_{\text{domain}} = \text{HKDF-Expand-SHA256}(\text{PRK}, \text{"ShellGuard-Domain-" + ns}, 32)$ across namespaces (`vault_pearls`, `vault_secure_notes`, `vault_credit_cards`, `vault_identities`, `vault_ssh_keys`, `vault_attachments`, `vault_pearls_history`, `pods`, `settings`, `export`). When operating over cleartext RFC 1918 LAN HTTP where `crypto.subtle` is context-restricted, key derivation routes transparently through the audited pure-TypeScript `@noble/hashes` HKDF-SHA256 fallback.

Derived `CryptoKey` handles are quarantined inside the `ShellGuardSessionVault` IndexedDB object store via `structuredClone` with `extractable: false` so keys survive MV3 service worker idle sleep cycles while remaining mathematically un-exportable to JavaScript byte arrays. Any vault lock event, inactivity alarm expiration, or 3-strike PIN failure immediately deletes the `ShellGuardSessionVault` store and overwrites transient key buffers in RAM.
