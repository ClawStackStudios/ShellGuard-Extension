# Autofill Law: Co-Presence Gate, Closed Shadow DOM & Pristine Injection

**Visual Oracles:** `docs/stitch/screen_7_inpage_overlay.png` and `docs/stitch/screen_13_inpage_glyph_states.png`.

Content scripts operate in untrusted host DOM space and never hold master keys, raw vault caches, or persistent plaintext credentials. Form scanning suppresses in-field glyphs on standalone text/search inputs unless an `input[type="password"]` is co-present in the container or the origin matches the verified multi-step signin whitelist; prompts inside cross-origin iframes (`window.top !== window.self`) or on page load without user gesture fail closed unconditionally. All injected glyphs, dropdowns, and capture pills mount inside `host.attachShadow({ mode: 'closed' })` with `adoptedStyleSheets` locked to absolute pixel metrics (`13px` base) and dynamically shift left by `12px + siblingWidth + 8px` (up to `68px`) whenever `ResizeObserver` detects a native password-reveal eye or clear button inside the input container.

When an operator triggers JIT autofill (`[Fill]` click or `Ctrl+Shift+L`), the content script requests a single-use credential payload for the verified tab origin, writes values exclusively via the pristine native descriptor (`Object.getOwnPropertyDescriptor(window.HTMLInputElement.prototype, 'value')?.set?.call(input, secret)`) to defeat host-page prototype pollution, dispatches bubbling `input` and `change` events for reactive framework synchronization, and zeroizes the transient variable in `<1ms`.
